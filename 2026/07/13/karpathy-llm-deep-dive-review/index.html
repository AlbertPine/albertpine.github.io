观后感：安德烈·卡帕西深度探索像ChatGPT这样的大语言模型

原视频（YouTube）：Deep Dive into LLMs like ChatGPT - Andrej Karpathy
B站搬运：深度探索像ChatGPT这样的大语言模型

一、为什么要看这个视频

Andrej Karpathy，这个名字在 AI 圈子里可以说是如雷贯耳——OpenAI 创始成员、前 Tesla AI 总监，也是最早向大众普及”大语言模型是如何工作的”这类知识的人之一。2025 年 2 月，他发布了一段长达 3 小时 31 分钟的全面教程，从零开始把 ChatGPT 这类大语言模型（LLM）的技术全栈拆解得清清楚楚。

作为一个天天用 ChatGPT 却对它的内部运作一知半解的人，看完之后最大的感受是：原来那些神秘的能力，都有清晰的技术脉络可循；而那些匪夷所思的错误，也都有其根深蒂固的起因。

下面是我看后整理的笔记和思考。

二、Tokenization：一切的起点

“计算机不认字，只认数。”

这是整个旅程的入口。我们要给模型喂文本，但神经网络只能处理数字，怎么办？答案就是 分词（Tokenization）。

Karpathy 用了很长的篇幅讲这个看似”枯燥”的话题，但看完才明白——Tokenization 的影响贯穿始终，模型的很多奇怪行为都可以追溯到这一步。

字节对编码（BPE）

具体做法是：

  1. 先把文本转成 UTF-8 字节序列（256 个基础符号）
  2. 统计所有频繁出现的字节对，把最常见的合并成一个新 token
  3. 不断迭代合并，直到词汇表达到预设大小（GPT-4 大约 10 万个 token）

这样的设计有一个核心权衡：词汇表大 → 每个 token 携带更多信息，序列短，但模型要学的 embedding 就多；词汇表小 → 更紧凑，但序列变长，计算量增加。

Tokenization 留下的”后遗症”

Karpathy 举了好几个让人哭笑不得的例子：

  • “strawberry 里有几个 r？” 模型经常答错。为什么？因为它看到的不是字母，而是 token（可能 straw 和 berry 是两个 token），没法直接数出 r 的个数。
  • 计数任务极差。也是同理——模型在 token 层面运行，字符级感知是间接的。
  • 拼写能力弱。让模型倒着拼一个单词，它常常翻车。

这些不是 bug，而是 tokenization 这种设计的固有代价。理解这一点后，很多 LLM 的”弱智”时刻就能解释了。

三、Transformer：模型的骨架

如果把 LLM 比作一栋大厦，Transformer 就是它的钢筋骨架。

自注意力机制（Self-Attention）

这是整个架构的灵魂。简单说：每个 token 在生成自己含义的同时，会”关注”序列中所有其他 token。 比如在句子 “The cat sat on the mat” 里，处理 cat 时模型会关注 sat（猫做什么），处理 mat 时会关注 on（垫子上）——这种全局依赖关系在自注意力机制中一步到位。

多头注意力（Multi-Head Attention）

单头注意力可能只会关注一种关系，多头注意力则并行运行多个注意力”镜头”——有的头捕捉语法结构，有的头关注语义关联，有的头可能追踪代词指向。这样模型就能同时理解语言的不同维度。

完整结构

每一个 Transformer Block 做的事情其实不复杂：注意力层负责”交流”（让 token 之间互通信息），前馈网络负责”思考”（对每个 token 单独做非线性变换），层归一化和残差连接保证训练稳定。

下一 token 预测：简单到令人发指的目标

这么复杂的架构，训练目标却出奇简单：给定前文，猜下一个 token 是什么。 交叉熵损失——越大越不准，越小越准。所有 1.6B、175B、1.8T 参数的海量计算，全部服务于这个看似幼稚的任务。

这也是 Karpathy 反复强调的核心直觉：LLM 本质上是一个”下一 token 预测器”。 整个预训练阶段就是这个预测器在海量互联网文本上的不断练习。

四、预训练：把互联网装进参数里

数据管线

预训练的第一步是搞到足够多、足够好的数据。Karpathy 详细描述了这条管线：

  1. 爬取：从 Common Crawl 这类来源获取原始网页，动辄 44TB 起步
  2. 过滤：去除恶意网站、垃圾信息、成人内容、导航栏等非正文元素
  3. 语言筛选：用分类器保留目标语言
  4. 去重 & PII 移除：删除重复内容和身份证号、电话号码等隐私信息
  5. 最终产出：数万亿 token 的高质量训练语料（如 Llama 3 用了大约 15 万亿 token）

训练过程

Karpathy 展示了他用 nanochat（一个约 7000 行 Python 代码的全栈实现）训练 GPT-2 规模模型的全过程。你可以亲眼看到 loss 从一开始的”胡乱猜测”逐渐下降到能生成连贯文本。训练到 ~100B token 后，模型已经能够：

  • 模仿互联网文档的各种风格
  • 续写故事、生成代码、回答问题
  • 展现出一种”知道很多东西”的错觉

但这里有一个关键认知：基础模型 ≠ ChatGPT

预训练产出的 只是一个”互联网文档模拟器”——给它一段开头，它续写下去，风格像极了互联网上的各类文本。它没有任何”助人意念”，不知道什么是对、什么是错，你问它”怎么学编程”，它可能给你续写一篇论坛帖子——包括你还没说完的下半句提问，甚至模拟出评论区争论。

让它从”文档模拟器”变成”有用助手”的，是下一步——后训练。

五、后训练：从文档生成器到对话助手

监督微调（SFT）

这是后训练的第一阶段。核心思路很简单：

  • 请人工标注员编写理想的对话——给定用户 prompt，写出一个 helpful、truthful、harmless 的理想回复
  • 用这些对话数据继续训练基础模型
  • 模型学到的就是：当看到 <|im_start|>user 开头的内容时，应该以 <|im_start|>assistant 开头生成有帮助的回复

Karpathy 提到了 OpenAI 的关键论文 InstructGPT，首次公开描述了这套方法。现代的 SFT 数据越来越多地使用合成数据——用更强的模型来生成训练数据，标注员更多是”编辑”而非”从零编写”。

价值观注入

SFT 不仅是教会模型对话格式，更关键的是注入价值观——什么是有帮助的、什么是真实的、什么是有害的。标注员拿着一本厚厚的标注指南，精确判断每个回复是否符合标准。这一步本质上是在”捏”模型的行为。

六、幻觉与”瑞士奶酪式智能”

Karpathy 在这一部分最让我印象深刻。他没有神化 LLM，而是用非常坦诚的态度分析了它的缺陷。

幻觉（Hallucination）

“模型会自信地编造虚假信息——因为它是统计预测器，不是事实核查引擎。”

这是最核心的一句话。LLM 在做的事情是：给定上文，预测最可能的下一个 token。 它不是在”回忆事实”，而是在做概率估算。当训练数据中存在知识空白，模型不会诚实地说”我不知道”——它会”编”一个看起来最合理的 token 序列。

这也解释了为什么幻觉看起来往往很真：模型被优化去生成流畅、连贯、看似合理的文本，这正是它的强项。而真实性，反而是事后注入的。

知识截止

模型参数固化在训练结束时。训练之后发生的事——新的事件、新的发现、新的流行词——模型一概不知。这就是为什么我们需要工具使用（搜索增强）。

“瑞士奶酪”式智能

Karpathy 用了一个精妙的比喻：LLM 的能力像瑞士奶酪——有的地方非常扎实，有的地方全是空洞。 它可能解出一道复杂的微积分题，却在”9.11 和 9.9 哪个大”这种问题上犯错。因为它的知识分布不均匀，取决于训练数据中的覆盖密度。

如何缓解缺陷

  • 工具使用：让模型在需要时调用搜索、计算器、代码解释器，而不是纯凭”记忆”做事
  • 思维链（Chain of Thought）：引导模型把推理过程分布在多个 token 上——因为每个 token 的计算量恒定，复杂问题必须”一步步想”

七、强化学习：让模型超越模仿

这是全视频最令人兴奋的部分。Karpathy 用了一个教育类比贯穿始终：

阶段 类比 说明
预训练 阅读教科书 大量接触语言，建立基础知识
SFT 学习例题 模仿专家的做法
强化学习 做练习题 通过试错自己发现规律

可验证领域的 RL

在数学、编程这类答案对错可以自动判断的领域，RL 几乎是开挂：

  1. 模型生成多个候选解答
  2. 检查答案是否正确
  3. 对正确解给予奖励，通过 RL 算法回传更新参数
  4. 模型逐渐学会”怎样思考才能答对”

关键洞见：SFT 只能让模型模仿人类专家，而 RL 可以让模型发现超越人类专家的策略。

DeepSeek-R1 的惊艳表现

Karpathy 特别提到了 DeepSeek-R1。经过 RL 训练后，模型展现出了自发涌现的推理行为：

  • 自动分解复杂问题为多个子步骤
  • 自我评估中间结果
  • 发现错误时回溯修正
  • 甚至出现”灵光一现”般的策略调整

这些能力不是被显式编程进去的——是 RL 过程中自然产生的。

AlphaGo 的 Move 37

Karpathy 提到了 AlphaGo 的经典时刻：Move 37，一步人类棋手起初都看不懂的棋，后来被证明无比精妙。他的核心观点是：RL 有潜力创造超越人类已有知识体系的新策略。 同样的道理正在 LLM 推理能力上重演。

RLHF：基于人类反馈的强化学习

但对于创意写作、摘要总结这类没有标准答案的任务，怎么用 RL？答案是让人类来做判断：

  1. 对同一个 prompt 生成多个回复
  2. 人类标注员进行排序（而非绝对打分——排序比打分容易得多）
  3. 用这些排序数据训练一个奖励模型，去模拟人类的偏好
  4. 用 PPO 算法优化主模型，最大化奖励模型的分数

Karpathy 也坦诚指出了 RLHF 的局限：奖励模型是”人类偏好的有损压缩”，可能被模型钻空子——生成看似高分但实际质量不高的输出。RLHF 不等于真正的 RL。

八、几个让我醍醐灌顶的金句

回顾全片，以下几个观点彻底重构了我对 LLM 的认知：

“LLM 是互联网的有损压缩。”

数十万亿 token 的互联网文本，被压缩进几百 GB 的参数文件中。这解释了为什么模型能”知道”那么多东西，但也解释了为什么精确性是个问题——有损压缩必然丢失细节。

“ChatGPT 不是一个神奇的 AI，而是对人类标注员行为的统计模拟。”

这句话祛魅了。ChatGPT 的”人格”其实来自 SFT 和 RLHF 阶段注入的人类偏好的统计平均。它的”友好””细致”是训练出来的，不是自发产生的。

“把 LLM 当作一个工具来使用，一个偶尔会有奇思妙想、偶尔会犯低级错误的工具。”

既不高估也不低估——这是我收获的最务实的态度。

“模型需要 token 来思考。”

每个 token 位置的计算量是固定的，复杂的推理必须”摊开”在多个 token 上。这就是为什么让模型”一步步想”比让它”直接回答”效果好得多。

九、写在最后

Karpathy 的这场分享不像很多 AI 科普那样要么过度神秘化、要么过度简化。他用 3.5 小时把一个技术主题讲得既专业又通透，其中穿插的直觉和金句让我受益很久。

了解这些机制后，我日常使用 ChatGPT 的方式也在慢慢改变：

  • 不再问”strawberry 里几个 r”然后嘲笑它笨——这是 tokenization 的锅
  • 开始主动用思维链引导复杂的分析任务
  • 对模型输出保持”信任但验证”的态度
  • 理解了幻觉不是 bug，而是统计模型的固有属性

如果你对 LLM 有一点好奇，或者想真正理解你每天用的 AI 助手到底是什么原理，这 3.5 小时值得投入。B 站上有翻译版，开 1.5 倍速，一个下午就能收获对整个 LLM 技术栈的结构化认知。
